# context-injection

## What it does

On every `Read`/`Edit`/`Write`/`Glob`/`Grep`, two PreToolUse hooks run: `inject-readme-context.mjs` walks from the tool's target path up the git-repo tree (`ancestorsUpTo`) collecting each directory's `AUTO_DOCS.md` + `CLAUDE.md`, while `inject.mjs`'s `injectionPlan()` relativizes the target against the host repo root and runs `match(systems, rel)` against `docs/systems/*.md` glob front-matter. Both dedup per-session and emit their payload through `hookSpecificOutput.additionalContext` so the docs land in the model's next view without the agent ever asking for them.

## Anchors

- `systems-registry/inject.mjs` — system-level hook; `injectionPlan()` glob-matches the target against `docs/systems/*.md` and emits the matched system's Mermaid + link via the `additionalContext` envelope.
- `docgen/inject-readme-context.mjs` — ancestor-walk hook; finds AUTO_DOCS.md/CLAUDE.md up the tree, dedups by content hash, emits per-dir prose.
- `hooks/hooks.json` — plugin-mode wiring registering both inject hooks under the `Read|Edit|Write|Glob|Grep` matcher (plus PostToolUse refresh and SessionStart/PreCompact dedup reset).
- `hooks/settings.json` — host-repo template snippet (`scripts/install.sh` merges it) wiring the same hooks at `tools/codecontext/` submodule paths.
- `systems-registry/inject.test.mjs` — the `injectionPlan()` truth table: documents every `reason` code (`injected`/`deduped`/`out-of-repo`/`no-match`/`system-page`/`tool-no-paths`) as an executable spec.

## Closing arrow

The loop closes through the model's context, not a network call: each hook writes a `hookSpecificOutput.additionalContext` JSON envelope to stdout, which Claude Code appends to the **next LLM turn**. When that turn touches another globbed/nested file, the PreToolUse matcher fires again — the agent's own tool calls drive re-entry. Per-session `/tmp/*-injected-<sid>.json` dedup files (reset by `reset-inject-dedup.mjs` on SessionStart/PreCompact) keep the loop from re-emitting identical context on every Read.

## Decision logic

Each hook independently decides whether to inject:
- **Target resolution** — `extractTargetPath` / `targetPathFrom` pull a path from `file_path`, `Glob` `path`/`pattern` (wildcards stripped to an anchor dir), or `Grep` `path`; tools not in `TOOLS_WITH_PATHS` fall through silently.
- **docgen** anchors at the git repo root (`git rev-parse --show-toplevel`), walks at most `MAX_ANCESTORS=6` dirs upward, skips targets whose basename is in `NOOP_BASENAMES` (`AUTO_DOCS.md`, `CLAUDE.md`) — but still records them as seen — and dedups by **content hash** (`contentHash` = 16 hex of sha1) so byte-identical docs across worktrees inject once. Ancestor docs contribute only their `## Purpose` body via `extractPurpose`.
- **systems-registry** resolves the **host** repo root (`findRepoRoot` prefers `payload.cwd`, then `--show-superproject-working-tree` to escape a submodule), rejects out-of-repo (`rel.startsWith('..')`) and `docs/systems/` self-targets, then emits each matched system once — dedup keyed by **system name**. `injectionPlan()` returns a `reason` code so `main()` can fire telemetry only on `injected`/`deduped`.

## Invariants

- Hooks NEVER block: every error path exits 0 with no output (`inject-readme-context.mjs` top comment; `inject.mjs:main` try/catch + `exitedOk`). A non-zero exit would block the agent's tool call — verified by the "never throws on garbage/empty stdin" tests.
- Injected context is capped at `MAX_CONTEXT_CHARS = 10000` per fire (`inject.mjs`); per-doc bytes capped at `MAX_README_BYTES = 6 * 1024`; ancestor walk capped at `MAX_ANCESTORS = 6`.
- Only the `hookSpecificOutput.additionalContext` JSON envelope reaches the model — plain stdout from a PreToolUse hook goes to the user transcript, not Claude's context.
- docgen dedups by **content hash**, systems-registry by **system name** — keys differ deliberately so identical docs across worktrees collapse to one injection.
- docgen injects `AUTO_DOCS.md` + `CLAUDE.md` only; a hand-written `README.md` is deliberately ignored (humans own it) — asserted by the "IGNORES a hand-written README.md" test.

## Failure modes

- **Submodule root mis-detection**: if `findRepoRoot` resolves the submodule instead of the host repo, `loadAll` finds 0 systems and the hook exits silently — the historical bug the `--show-superproject-working-tree` candidate fixes.
- **Stale dedup**: if `reset-inject-dedup.mjs` fails to clear `/tmp` state on SessionStart/PreCompact, a doc edited mid-session won't re-inject its updated content (still keyed as "seen").
- **Telemetry reference-bug class**: docgen's `tool` was hoisted into `main` scope precisely because referencing an out-of-scope var threw on every fire and was swallowed by the no-throw guard — silent telemetry loss with no surfaced error; the telemetry-parity tests now guard against regression.
- **Truncation**: a system page (or stack of ancestor docs) exceeding the 10k cap is silently sliced, so very large manifests lose their tail in-context.
- **Outside a git repo**: `repoRoot`/`findRepoRoot` returns null and nothing injects — expected, but scratch dirs get no context.
