# Cross-dir fixture — ideal Pass 1 hypothesis

This is the CRITICAL test for v2: the heuristic Pass 0 cannot detect
this system because its pieces span 3 different top-level dirs. Pass 1
SHOULD identify it as one unified system.

## Expected systems

```yaml
systems:
  - name: event-processor
    summary: |
      An event-processing pipeline that spans three dirs: apps/api
      hosts the Processor class, packages/shared defines the Event
      type contract, scripts/relay.sh is the downstream relay invoked
      via spawn.
    globs:
      - apps/api/**
      - packages/shared/event.ts
      - scripts/relay.sh
    closes_loop_via: |
      Processor.handle() spawns scripts/relay.sh per event;
      relay loops indefinitely; state goes to processor-state.json.
    consumes: []
```

## Scoring notes

- This is the LOAD-BEARING test for v2. If Pass 1 fails this fixture,
  the whole hypothesis pass is delivering no value over Pass 0.
- Pass 1 must reunify all three dirs into ONE system.
- Acceptable name variants: event-processor, event-pipeline, processor-relay.
- All three globs must be present in some form.

## Calibration thresholds

- Score 10: single unified system, all three dir-files in globs
- Score 8: single system but missed one of the three globs
- Score 6: fragmented into 2 systems but they reference each other
- Score ≤4: fragmented into 3 separate systems, OR completely missed
