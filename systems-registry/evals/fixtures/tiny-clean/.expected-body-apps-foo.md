```markdown
# apps-foo

## What it does

The runFoo() coordinator orchestrates three modules in a continuous
loop: capture.mjs takes a snapshot, score.mjs reduces it, the result
is written to state.json on disk, and a child process is spawned via
node:child_process.

## The loop

\`\`\`mermaid
flowchart LR
  start[runFoo enters loop] --> snap[capture takes snapshot]
  snap --> score[score reduces snapshot]
  score --> persist[writeFileSync state.json]
  persist --> spawn[spawn echo tick]
  spawn --> start
\`\`\`

## Anchors

- `apps/foo/run.mjs` — coordinator, imports capture + score, runs the loop
- `apps/foo/capture.mjs` — exports capture() which returns {now: Date.now()}
- `apps/foo/score.mjs` — exports score(snap) which returns snap.now % 100

## Closing arrow

Each tick produces a state.json write + a spawned subprocess. The loop
has no exit condition — it runs forever once entered.

## Invariants

- run.mjs imports capture and score from sibling files only
- state.json gets overwritten every tick (no append, no history)
- No process arguments, no env vars consumed

## Failure modes

- writeFileSync error (disk full / permission) crashes the loop
- spawn() failure (echo missing) crashes the loop
- score returns undefined → state.json contains undefined-as-string

## Where to start reading

1. `apps/foo/run.mjs` — the loop entry point
2. `apps/foo/capture.mjs` — what's captured
3. `apps/foo/score.mjs` — how it's scored
```

- **8**: All sections present but one minor inaccuracy (e.g., summary
  slightly off, or one anchor missing detail).
- **6**: Missing 1 section or has a minor hallucination.
- **4**: Mermaid invalid OR hallucinated file paths OR missing 2 sections.
- **2**: Body is generic / could describe any system.
- **0**: Empty, completely wrong, or unparseable.
