# Tiny-clean fixture — ideal Pass 1 hypothesis

This is the human-written ground truth for what Pass 1 SHOULD produce
on the tiny-clean fixture. The judge LLM scores actual Pass 1 output
against this.

## Expected systems

```yaml
systems:
  - name: apps-foo
    summary: |
      A tick-loop runner that captures a snapshot, scores it, writes
      state to disk, and spawns a child process. Three coordinated
      modules: run.mjs (orchestrator), capture.mjs (snapshot), score.mjs.
    globs:
      - apps/foo/**
    closes_loop_via: |
      Writes state.json each tick; the spawn() call is the side effect.
    consumes: []

  - name: tools-bar
    summary: |
      A CLI loop that imports lib + run, writes bar-state.json,
      and spawns child processes via spawnSync.
    globs:
      - tools/bar/**
    closes_loop_via: |
      Writes bar-state.json each iteration; spawnSync triggers the
      external command per tick.
    consumes: []
```

## Scoring notes

- Pass 1 MUST identify both `apps-foo` and `tools-bar` as distinct systems.
- Globs may be slightly different (`apps/foo/*` vs `apps/foo/**`) — judge tolerates.
- Pass 1 should NOT invent cross-system relationships that don't exist.
- It's fine if Pass 1 finds extra real signal we missed, but flag any
  hallucinated systems.

## Calibration thresholds

- Score 10: both systems present, accurate summaries, no hallucinations
- Score 8: both present but summaries off by one detail
- Score 6: only one system found, or both with significantly wrong globs
- Score ≤4: missed systems entirely or hallucinated extras
